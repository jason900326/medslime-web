# MedSlime 抽卡／金幣平衡 v1

> 本文件記錄目前正式程式實際採用的遊戲規則。調整機率、保底或重複回饋時，必須同步更新程式與本文件。

## 角色池

目前圖鑑共 17 隻：

- N：4 隻
- R：6 隻
- SR：6 隻
- SSR：1 隻

## 抽卡機率

目前實作機率：

- N：45%
- R：37%
- SR：17.7%
- SSR：0.3%

### 保底與收集保護

- SSR 最晚第 80 抽保底。
- 10 連抽保證至少出現 1 隻 SR 以上角色。
- 同稀有度中，會優先抽到尚未擁有的角色；該稀有度全部收齊後，才會在該稀有度角色中隨機抽取。

## 抽卡消耗

- 單抽：100 金幣
- 十抽：1,000 金幣
- 每日免費抽：1 次
- 抽卡券：1 張 = 1 抽

## 重複角色回饋

抽到已擁有的史萊姆時，不再產生碎片或飾品進度，直接依稀有度返還金幣：

- N：+20 金幣
- R：+35 金幣
- SR：+60 金幣
- SSR：+150 金幣

**現行規則：重複角色 → 金幣。**

重複退款低於單抽成本，避免抽卡形成正回饋循環；高稀有度提供較高回饋，用來降低重複高稀有度角色的挫折感。

## 飾品／碎片系統狀態

飾品與碎片系統已退場：

- 不再因重複角色獲得碎片。
- 不再以碎片解鎖專屬飾品。
- 遊戲 state 不應再保存 `fragments`、`accessoryUnlocked`、`accessoryEquipped`。
- 角色定義不應再保存 `accessory`、`accessoryImage`。
- 舊 accessory 圖片僅視為歷史資產，不參與目前遊戲邏輯。

資料庫舊欄位／舊 state 的清理以 `supabase/remove_slime_accessories.sql` 為準；已執行過的正式環境不要重複做人工資料轉換。

## 目前要觀察的數據

1. 第一次 SSR 平均出現在第幾抽。
2. 7 / 30 / 60 / 100 天平均收藏數。
3. 玩家每日平均抽數。
4. 金幣每日淨增減。
5. 重複角色退款對金幣通膨的影響。
6. 17 / 17 圖鑑完成所需的平均時間。

> 後續若要重新平衡，應以真實使用資料校正；不要只改 UI 顯示而未同步修改 `components/game-state-provider.tsx`。
